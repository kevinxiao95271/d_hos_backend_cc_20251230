## 1. 系统概述

### 1.1 服务信息
- **基础URL**: `http://localhost:8080/dgear`
- **API文档**: `http://localhost:8080/dgear/swagger-ui.html`
- **Druid监控**: `http://localhost:8080/dgear/druid/`

### 1.2 统一响应格式
所有接口返回统一的JSON格式：

```json
{
  "code": 200,           // 状态码：200-成功，其他-失败
  "message": "操作成功",  // 返回消息
  "data": {},            // 返回数据
  "timestamp": 1767864206969  // 时间戳
}
```

### 1.3 核心概念

#### 指标项（IndicatorItem）
- 最小的数据采集单元
- 包含SQL查询语句
- 用于从数据库获取原始数据
- 示例：`a0050`（肺炎病种例数）

#### 指标（Indicator）
- 由一个或多个指标项通过表达式计算得出
- 支持树形层级结构
- 分为叶子节点（可计算）和非叶子节点（分类节点）
- 示例：`肺炎平均住院日 = a0052/a0050`

系统提供三大类接口：

```javascript
headers: {
```

## 3. 指标项管理接口

### 3.1 查询所有指标项列表
**接口**: `GET /api/indicator-item/list`

**请求示例**:

```json

  "message": "操作成功",
  "data": [

      "itemCode": "total_patients",
      "itemName": "总患者数",
      "itemType": "COLLECTED",

      "querySql": "SELECT COUNT(*) AS result_value FROM d_mr...",
```

```javascript
const params = new URLSearchParams({
```

### 3.5 新增指标项（RESTful风格）
**接口**: `POST /api/indicator-item`

**请求体**:
```json
{
  "itemCode": "test_item_001",
  "itemName": "测试指标项",
  "itemType": "COLLECTED",
  "dataSource": "D_MR",
  "querySql": "SELECT COUNT(*) AS result_value FROM d_mr WHERE...",
  "unit": "人",
  "status": 1,
  "sortOrder": 999,
  "remark": "备注信息"
}
```

**请求示例**:
```javascript
fetch('http://localhost:8080/dgear/api/indicator-item', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({
    itemCode: 'test_item_001',
    itemName: '测试指标项',
    itemType: 'COLLECTED',
    dataSource: 'D_MR',
    querySql: 'SELECT COUNT(*) AS result_value FROM d_mr',
    unit: '人',
    status: 1,
    sortOrder: 999
  })
})
.then(res => res.json())
.then(data => console.log(data));
```

**字段说明**:
- `itemCode`: 指标项编码（必填，唯一）
- `itemName`: 指标项名称（必填）
- `itemType`: 指标项类型（必填）
  - `COLLECTED`: 采集型
  - `CALCULATED`: 计算型
- `dataSource`: 数据源表名
- `querySql`: SQL查询语句（支持参数 `#{startDate}` 和 `#{endDate}`）
- `unit`: 单位
- `status`: 状态（0-禁用，1-启用）
- `sortOrder`: 排序号

### 4.6 新增指标（RESTful风格）
**接口**: `POST /api/indicator`

**请求体**:
```json
{
  "metricCode": "99.1",
  "metricName": "测试指标",
  "parentCode": "99",
  "indicatorLevel": 2,
  "isLeaf": 1,
  "metricType": "QUANTITATIVE",
  "calculationType": "EXPRESSION",
  "expression": "a0050/a0052",
  "relatedItems": "[\"a0050\",\"a0052\"]",
  "unit": "天",
  "supportDeptDrill": 1,
  "status": 1,
  "sortOrder": 999,
  "remark": "备注信息"
}
```

**请求示例**:
```javascript
fetch('http://localhost:8080/dgear/api/indicator', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({
    metricCode: '99.1',
    metricName: '测试指标',
    parentCode: '99',
    indicatorLevel: 2,
    isLeaf: 1,
    metricType: 'QUANTITATIVE',
    calculationType: 'EXPRESSION',
    expression: 'a0050/a0052',
    relatedItems: '["a0050","a0052"]',
    unit: '天',
    supportDeptDrill: 1,
    status: 1,
    sortOrder: 999
  })
})
.then(res => res.json())
.then(data => console.log(data));
```

**字段说明**:
- `metricCode`: 指标编码（必填，唯一）
- `metricName`: 指标名称（必填）
- `parentCode`: 父级指标编码
- `indicatorLevel`: 指标层级（1-顶级，2-二级...）
- `isLeaf`: 是否叶子节点（0-否，1-是。只有叶子节点可以计算）
- `metricType`: 指标类型（必填）
  - `QUANTITATIVE`: 定量
  - `QUALITATIVE`: 定性
- `calculationType`: 计算类型（必填）
  - `ITEM`: 直接使用指标项的值
  - `EXPRESSION`: 使用表达式计算
  - `NONE`: 不计算（分类节点）
- `expression`: 计算表达式（如：`a0050/a0052` 或 `SUM(a0050)/SUM(a0052)`）
- `relatedItems`: 关联的指标项编码JSON数组（如：`["a0050","a0052"]`）
- `unit`: 单位
- `supportDeptDrill`: 是否支持科室下钻（0-否，1-是）
- `status`: 状态（0-禁用，1-启用）
- `sortOrder`: 排序号

## 5. 指标计算与结果查询接口

### 5.1 执行单个指标计算
**接口**: `POST /api/indicator-result/calculate`

**请求参数**:
| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| metricCode | String | 是 | 指标编码 |
| timeDimension | String | 是 | 时间维度：YEAR/QUARTER/MONTH/DAY |
| startDate | String | 是 | 开始日期，格式：yyyy-MM-dd |
| endDate | String | 是 | 结束日期，格式：yyyy-MM-dd |

**请求示例**:
```javascript
const params = new URLSearchParams({
  metricCode: '急性心肌梗死平均住院日',
  timeDimension: 'YEAR',
  startDate: '2023-01-01',
  endDate: '2023-12-31'
});

fetch(`http://localhost:8080/dgear/api/indicator-result/calculate?${params}`, {
  method: 'POST'
})
.then(res => res.json())
.then(data => console.log(data));
```

**响应示例**:
```json
{
  "code": 200,
  "message": "指标计算成功",
  "data": {
    "id": 1,
    "metricCode": "急性心肌梗死平均住院日",
    "timeDimension": "YEAR",
    "timeValue": "2023",
    "startDate": "2023-01-01",
    "endDate": "2023-12-31",
    "resultValue": 12.5,
    "resultJson": "{\"metric_code\":\"急性心肌梗死平均住院日\",\"result_value\":12.5,\"item_values\":{\"a0034\":250,\"a0032\":20}}",
    "calculationStatus": "SUCCESS"
  }
}
```

### 5.2 批量计算指标
**接口**: `POST /api/indicator-result/batch-calculate`

**说明**: 批量执行多个指标的计算，支持按时间维度自动拆分

**请求参数**:
| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| timeDimension | String | 是 | 时间维度：YEAR/QUARTER/MONTH/DAY |
| startDate | String | 是 | 开始日期 |
| endDate | String | 是 | 结束日期 |

**请求体**: 指标编码列表（为空时计算所有叶子指标）

**请求示例**:
```javascript
// 计算指定指标列表
fetch('http://localhost:8080/dgear/api/indicator-result/batch-calculate?timeDimension=MONTH&startDate=2023-01-01&endDate=2023-03-31', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify([
    '急性心肌梗死平均住院日',
    '心力衰竭平均住院日',
    '肺炎（住院、成人）平均住院日'
  ])
})
.then(res => res.json())
.then(data => console.log(data));

// 计算所有叶子指标
fetch('http://localhost:8080/dgear/api/indicator-result/batch-calculate?timeDimension=YEAR&startDate=2023-01-01&endDate=2023-12-31', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify([])  // 空数组表示计算所有叶子指标
})
.then(res => res.json())
.then(data => console.log(data));
```

## 7. 常见问题

### 7.1 重复计算结果如何处理？
**问题**: 如果多次执行同一个计算任务，由于源数据的变动导致多次的结果不一致，最终查询出来的结果是哪一个？

**答**: 系统采用**更新策略**。当多次计算同一指标（相同的指标编码+时间维度+时间值）时，**后面的计算会覆盖前面的结果**，始终保持最新的计算结果。

查询时获取的是**最后一次计算**的结果，`update_time`字段会记录最后计算时间。

### 7.2 时间维度说明
系统支持以下时间维度：
- `YEAR`: 按年统计（如2023）
- `QUARTER`: 按季统计（如2023-Q1）
- `MONTH`: 按月统计（如2023-01）
- `DAY`: 按日统计（如2023-01-15）

### 7.3 如何处理中文编码问题？
在Git Bash等环境中使用curl测试中文数据时可能出现UTF-8编码问题。建议：
1. 使用Swagger UI进行测试（[http://localhost:8080/dgear/swagger-ui.html](http://localhost:8080/dgear/swagger-ui.html)）
2. 使用Postman等GUI工具
3. 在前端应用中正确设置`Content-Type: application/json`并使用UTF-8编码

### 7.4 RESTful风格 vs 兼容接口
系统同时提供两种风格的接口：

**RESTful风格**（推荐）:
- 新增: `POST /api/indicator`
- 更新: `PUT /api/indicator/{id}`

**兼容接口**:
- 保存/更新: `POST /api/indicator/save`（根据是否有id判断）

建议前端统一使用RESTful风格接口。

### 7.5 表达式计算说明
指标计算支持两种类型：

1. **ITEM类型**: 直接使用指标项的值
   - `expression`: 指标项编码（如`a0050`）
   - `relatedItems`: `["a0050"]`

2. **EXPRESSION类型**: 使用表达式计算
   - 简单表达式: `a0050/a0052`
   - 聚合表达式: `SUM(a0050)/SUM(a0052)`
   - 支持运算符: `+`、`-`、`*`、`/`
   - `relatedItems`: 包含所有相关指标项（如`["a0050","a0052"]`）

### 7.6 科室下钻前提条件
并非所有指标都支持科室下钻，需要满足：
1. 指标的`supportDeptDrill`字段为1
2. 指标项的SQL需要关联科室信息
3. 数据库中存在科室维度数据

### 7.7 批量计算性能优化
批量计算时系统会根据时间维度自动拆分：
- `MONTH`维度：按月拆分计算
- `QUARTER`维度：按季拆分计算
- `YEAR`维度：按年计算

建议合理选择时间范围和维度，避免一次性计算过多数据。
